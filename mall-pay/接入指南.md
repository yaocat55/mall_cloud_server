# 支付服务接入指南

> mall-pay 统一支付服务——业务系统接入文档。
> 最后更新：2026-08-05

---

## 一、支付服务做了什么

业务系统不需要关心这些：

- 支付宝 SDK、微信 SDK 的调用和版本升级
- 渠道回调验签、解密、CAS 乐观锁防重处理
- 金额单位换算（元↔分）
- 主动查单兜底（回调丢失时轮询，限时+分页）
- MQ 通知发送和失败重推（退避补偿）
- 超时关单（30 分钟后自动关闭 + 通知业务方释放资源）
- 日终对账（下载渠道账单 → 与本地逐笔比对 → 差异告警）
- 退款审核、退款累计冲正

业务系统只需要：**下单时调一个接口拿拉起参数 → 写一个 MQ 消费者收支付结果**。

## 二、接入步骤

### Step 1: Maven 依赖

```xml
<dependency>
    <groupId>cn.net.mall</groupId>
    <artifactId>mall-pay-client</artifactId>
    <version>1.0.0</version>
</dependency>
```

### Step 2: 注册业务方

在支付库 `pay_biz_config` 表插入一行，分配唯一的 `biz_type`：

```sql
INSERT INTO pay_biz_config (biz_type, biz_name, notify_mq_topic, notify_mq_tag, status)
VALUES ('MEMBER_RECHARGE', '会员充值', 'PAY_NOTIFY_MEMBER', 'PAY_SUCCESS', 1);
```

| 字段 | 说明 |
|------|------|
| `biz_type` | 业务类型编码，全支付库唯一（如 `MALL_ORDER`、`MEMBER_RECHARGE`） |
| `biz_name` | 业务方中文名，仅展示用 |
| `notify_mq_topic` | 支付成功后 MQ 通知的 Topic |
| `notify_mq_tag` | MQ Tag（可选，用于消费端过滤） |

> 插完这行，支付库**零表结构改动**，无需改任何代码。

### Step 3: 下单时调用创建支付单

业务系统下单成功后，通过 Feign 调用支付服务：

```java
@Autowired
private PayFeignClient payFeignClient;

// 下单成功后：
PayCreateDTO payCreate = new PayCreateDTO();
payCreate.setBizOrderNo(order.getCode());          // ✅ 必须：你的订单号
payCreate.setBizType("MEMBER_RECHARGE");           // ✅ 必须：你的业务类型（与 pay_biz_config 一致）
payCreate.setChannelCode(submitDTO.getChannelCode()); // ✅ 必须：ALIPAY / WECHAT_PAY / WECHAT_MINI
payCreate.setUserId(order.getUserId());            // ✅ 必须：谁在付钱
payCreate.setTotalAmount(39900L);                  // ✅ 必须：应付金额（单位：分）
payCreate.setSubject("会员年卡充值");                // ⚠️ 建议：收银台展示用，缺失用 bizOrderNo 兜底
payCreate.setOpenId(submitDTO.getOpenId());        // ⚠️ 仅微信小程序必填，其他渠道可空
payCreate.setClientIp(request.getRemoteAddr());    // 可选：风控用

PayCreateResult result = payFeignClient.create(payCreate);

// 返回给前端：
// result.getPayOrderNo()    → 支付订单号（后续查询用）
// result.getPrepayParams()  → 拉起支付参数（支付宝 orderStr / 微信 prepay 参数串）
// result.getChannelCode()   → 渠道编码（前端据此决定怎么用 prepayParams）
```

### Step 4: 前端拉起支付

```javascript
// 支付宝：prepayParams 就是 orderStr，原样透传
AlipaySDK.pay(result.prepayParams)

// 微信 App：prepayParams 是 JSON，解析后调 SDK
const params = JSON.parse(result.prepayParams)
WechatSDK.pay(params)

// 微信小程序：同上，字段名是 paySign 不是 sign
wx.requestPayment(JSON.parse(result.prepayParams))
```

### Step 5: 消费 MQ 更新业务订单

写一个 RocketMQ 消费者，监听 `pay_biz_config` 里注册的 Topic：

```java
@Slf4j
@Service
@AllArgsConstructor
@RocketMQMessageListener(
        topic = "PAY_NOTIFY_MEMBER",               // 对齐 pay_biz_config.notify_mq_topic
        consumerGroup = "member_pay_success_group",
        selectorExpression = "PAY_SUCCESS",         // 对齐 pay_biz_config.notify_mq_tag
        consumeMode = ConsumeMode.CONCURRENTLY,
        messageModel = MessageModel.CLUSTERING)
public class MemberPaySuccessConsumer implements RocketMQListener<MessageExt> {

    private final MemberService memberService;
    private final ObjectMapper objectMapper;

    @Override
    public void onMessage(MessageExt messageExt) {
        PayNotifyMessage msg = objectMapper.readValue(
                new String(messageExt.getBody()), PayNotifyMessage.class);

        // 幂等：已处理过则跳过
        if (memberService.isPaid(msg.getBizOrderNo())) {
            return;
        }

        // 更新你的业务订单状态
        memberService.markPaid(msg.getBizOrderNo(), msg.getPayAmount());
    }
}
```

`PayNotifyMessage` 包含的字段：

| 字段 | 说明 |
|------|------|
| `payOrderNo` | 支付订单号 |
| `merchantOrderNo` | 渠道商户订单号 |
| `bizOrderNo` | 你的业务订单号（匹配键） |
| `bizType` | 你的业务类型 |
| `payAmount` | 实付金额（分） |
| `payStatus` | 20=已支付, 30=已关闭 |
| `channelCode` | 支付渠道 |
| `successTime` | 支付成功时间 |
| `notifyType` | "PAY"（支付）/ "REFUND"（退款）/ "CLOSED"（关闭） |

### 额外：退款

```java
PayRefundDTO refundDTO = new PayRefundDTO();
refundDTO.setPayOrderNo(payOrderNo);
refundDTO.setRefundAmount(5000L);  // 退 50 元（分）
refundDTO.setRefundReason("用户申请售后");

PayRefundResult result = payFeignClient.refund(refundDTO);
```

退款结果同样走 MQ 通知（`notifyType="REFUND"`），消费端按 `refundNo` + `refundStatus` 处理。

## 三、你必须提供的

| 序号 | 做什么 | 说明 |
|:---:|------|------|
| 1 | 分配一个 `bizType` | 全支付库唯一，如 `MALL_ORDER`、`MEMBER_RECHARGE` |
| 2 | 提供 MQ Topic | 支付成功/退款后往哪发消息 |
| 3 | 下单时调 `POST /v1/internal/pay/create` | 传 bizOrderNo + bizType + channelCode + userId + totalAmount |
| 4 | 写一个 MQ 消费者 | 收到 `PayNotifyMessage` 后更新业务订单状态（**必须幂等**） |
| 5 | 申请退款时调 `refund` | 传 payOrderNo + refundAmount |

**只有 5 件事。**

## 四、你不需要关心的

| 你不需关心 | 谁在做 |
|------|:---:|
| 支付宝/微信 SDK 怎么调 | mall-pay 渠道策略 |
| 回调验签、解密、CAS 防重 | mall-pay 回调控制器 |
| 金额单位（元/分）换算 | mall-pay 渠道策略内部 |
| 支付回调丢了怎么办 | mall-pay 主动查单兜底（限时+分页） |
| MQ 通知失败怎么办 | mall-pay 退避重推（NotifyCompensateJob 每分钟） |
| 支付超时了怎么办 | mall-pay 超时关单（PayOrderCloseJob 每 10 分钟） |
| 每天钱对不对 | mall-pay 日终对账 |
| 退款累计对不对 | mall-pay 退款冲正 |
| 新增一种支付方式 | mall-pay 加策略实现，业务方无感 |
| 渠道 SDK 升级 | mall-pay 升级，业务方无感 |

## 五、接入检查清单

- [ ] `pay_biz_config` 表已插入业务方记录（`bizType` + MQ Topic）
- [ ] 业务系统依赖了 `mall-pay-client`
- [ ] 下单后调用了 `PayFeignClient.create()`，传了 6 个必须字段
- [ ] 写了 MQ 消费者，监听对应 Topic
- [ ] MQ 消费者做了幂等（已支付/已关闭则跳过）
- [ ] `totalAmount` 单位是**分**（元 × 100）
- [ ] 小程序支付时传了 `openId`
- [ ] 退款时传了 `payOrderNo`（不是 bizOrderNo）

## 六、常见问题

**Q: 同一个订单重复调 create 会怎样？**

A: 幂等。按 `bizType + bizOrderNo` 查已有待支付单，存在则直接返回，不重复创建。

**Q: prepay 调了但用户没付，怎么办？**

A: 支付单保持待支付(10)，30 分钟后超时自动关闭（PayOrderCloseJob 每 10 分钟扫描过期单 → 关单 → MQ 通知业务方释放库存）。业务方也可主动调 `close` 释放。用户可重新发起支付。

**Q: MQ 消费者挂了，支付通知会丢吗？**

A: 不会。pay 侧 MQ 发送失败会标记 `bizNotifyStatus=2`，定时任务退避重推（1min/5min/15min/1h，最多 5 次）。5 次全失败后对账系统会在次日发现差异。

**Q: 金额为什么传分？**

A: 微信 SDK 金额单位是分，支付宝是元。支付服务内部统一用分存储（bigint），换算在各渠道策略内部完成。业务方传分即可，不用管渠道差异。

**Q: 怎么接多个业务方？**

A: 每个业务方分配不同的 `bizType`，各插一行 `pay_biz_config`，各自消费不同的 MQ Topic。支付表零改动。

## 七、架构总览

```
你的业务系统                        mall-pay（本服务）              支付宝/微信
═══════════                       ════════════════              ══════════

① 下单成功
   │
   ├─ PayFeignClient.create()
   │   └─→ 创建 pay_order ──→ prepay ──→ 返回拉起参数
   │
   ├─ prepayParams → 前端调起 SDK ───────────────────────────→ 用户支付
   │
   │                                 ◄── 渠道回调 ──────────────── 支付成功
   │                           验签 → CAS 10→20
   │                           MQ 通知 ──→ 你的消费者 ──→ 你的订单已支付 ✅
   │
   │                           查单兜底（5 分钟后无回调 → 轮询渠道确认）
   │
   │                           超时关单（30 分钟过期 → 关单 → MQ CLOSED 通知）
   │                                                       └─→ 释放库存
   │
   │                           次日 10:30
   │                           下载渠道账单 → 与 pay_order
   │                           逐笔比对 → 对平 / 差异告警
   │
   │                           MQ 通知补偿（失败重推退避，每秒/5分/15分/1h，5 次）
   │
   └─ 退款时调 refund()
        └─→ 审核 → 渠道退款 → MQ 通知退款结果 → 你的消费者处理
```

你的职责只有两个调用点（create + refund）和一个消费点（MQ），中间所有复杂逻辑全部在 mall-pay 内部。
