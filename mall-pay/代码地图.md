## 二、分层详解

### 1. channel/ — 渠道策略层

支付渠道的**唯一扩展点**——新增支付渠道只需新增一个实现类。

| 文件 | 职责 |
|------|------|
| `PayChannelStrategy.java` | 策略接口：定义 `prepay` / `query` / `close` / `refund` / `queryRefund` / `verifyNotify` / `parseNotify` / `downloadBill` / `parseBill` 9 个方法 |
| `alipay/AlipayChannelStrategy.java` | 支付宝 App 支付：基于 `alipay-sdk-java`，`AlipayClient` 从工厂获取（Caffeine 缓存），金额分↔元换算 |
| `wechat/WechatPayStrategy.java` | 微信 App 支付：基于 `wechatpay-java` SDK，`RSAAutoCertificateConfig` 从工厂获取，二次签名（5 行 SHA256withRSA），对账单下载 `BillDownloadServiceExtension` |
| `wechat/WechatMiniStrategy.java` | 微信小程序支付：与 App 支付共用同套 SDK，**差异**在二次签名 4 行（无 partnerId、paySign 字段名、package 格式） |
| `mock/MockChannelStrategy.java` | MOCK 模拟渠道：`mall.pay.mock.enabled=true` 时启用，直接返回成功，用于本地/测试环境联调 |

### 2. controller/ — 控制器层

#### C 端（mobile）

| 文件 | 路由 | 职责 |
|------|------|------|
| `mobile/PayController.java` | `/mobile/v1/pay/**` | C 端收银台：创建支付 → 发起 prepay → 查询支付结果。聚合 `PayCoreService` |

#### 内部 Feign（internal）

| 文件 | 路由 | 职责 |
|------|------|------|
| `internal/PayInternalController.java` | `/internal/v1/pay/**` | 内部服务间调用（不走网关）：`/create` 由 mall-order 通过 Feign 调用创建支付单 |

#### 渠道回调（notify）

| 文件 | 路由 | 职责 |
|------|------|------|
| `notify/AlipayNotifyController.java` | `/v1/notify/alipay` | 支付宝异步回调：`getParameterMap()` → `rsaCheckV1()` 验签 → `parseNotify()` → `handleNotify()` → 返回 `"success"` |
| `notify/WechatNotifyController.java` | `/v1/notify/wechat` | 微信异步回调：读 raw body + 请求头 → `NotificationParser.parse()` 验签+解密 → `handleNotify()` → 返回 `{"code":"SUCCESS"}` |

#### admin 前端直连接口

| 文件 | 职责 |
|------|------|
| `admin/PayOrderController.java` | 支付订单 CRUD |
| `admin/PayRefundController.java` | 退款单 CRUD |
| `admin/PayChannelConfigController.java` | 渠道配置管理（增删改时触发缓存淘汰） |
| `admin/PayBizConfigController.java` | 业务方配置管理 |
| `admin/PayNotifyLogController.java` | 通知日志查看 |
| `admin/ReconBatchController.java` | 对账批次查看 |
| `admin/ReconResultController.java` | 对账差异查看/处理 |
| `admin/ReconTempController.java` | 对账临时表查看 |

### 3. dto/ — 数据传输对象

| 文件 | 职责 |
|------|------|
| `PayCreateDTO.java` | 创建支付单入参（bizOrderNo, channelCode, amount, subject 等） |
| `PayCreateResult.java` | 创建支付单出参（payOrderNo, merchantOrderNo, prepayParams, payStatus） |
| `PayQueryDTO.java` | 查询支付单入参 |
| `PayQueryResult.java` | 查询支付单出参（status, channelTradeNo, payAmount, successTime） |
| `PayCloseDTO.java` | 关闭支付单入参 |
| `PayRefundDTO.java` | 退款申请入参 |
| `PayRefundResult.java` | 退款结果出参 |
| `PayRefundQueryDTO.java` | 退款查询入参 |
| `PayRefundQueryResult.java` | 退款查询出参 |
| `PayPrepayResult.java` | 渠道 prepay 返回值（prepayParams 为前端拉起 SDK 的 json） |
| `PayNotifyMessage.java` | 渠道回调统一消息体 → 驱动状态机 → 发 MQ |
| `BillRow.java` | 渠道对账单统一行结构（tradeNo, amount, fee, income 等），**对账引擎只认此结构** |
| `PayChannelDTO.java` | 前端收银台渲染渠道列表（channelCode + channelName，不暴露密钥） |

### 4. entity/ — 数据库实体 + 查询条件

#### 核心实体

| 文件 | 对应表 | 职责 |
|------|------|------|
| `PayOrderEntity.java` | `pay_order` | 支付订单（雪花 ID, payOrderNo, merchantOrderNo, channelCode, totalAmount, payAmount, refundAmount, payStatus, successTime…） |
| `PayRefundEntity.java` | `pay_refund` | 退款单 |
| `PayChannelConfigEntity.java` | `pay_channel_config` | 渠道配置（appId, merchantId, publicKey, privateKey, notifyUrl, configJson…） |
| `PayBizConfigEntity.java` | `pay_biz_config` | 业务方配置（bizType → MQ topic/tag） |
| `PayNotifyLogEntity.java` | `pay_notify_log` | 通知日志（回调原始报文 + 验签结果 + MQ 发送状态） |
| `ReconBatchEntity.java` | `recon_batch` | 对账批次（batchNo, channelCode, tradeDate, status, channelCount/platformCount/diffCount…） |
| `ReconTempEntity.java` | `recon_temp` | 对账临时表（按批次批量灌入渠道对账单，保留 N 天后物理删除） |

#### 查询条件（*ConditionEntity）

每个实体对应一个 `*ConditionEntity`（如 `PayOrderConditionEntity`），供 MyBatis XML `<sql id="queryWhere">` 动态条件拼装。

### 6. service/ — 业务服务层

#### 核心服务（有实质业务逻辑）

| 文件 | 职责 |
|------|------|
| `PayCoreService.java` | **支付主线**：创建支付单（生成雪花 ID + merchantOrderNo）→ 渠道 prepay → 回调 handleNotify（CAS 乐观锁 10→20 + 后置通知）→ 主动查单兜底（限时+分页+渠道 query） |
| `RefundCoreService.java` | **退款主线**：申请 → 自动审核（bizOrderNo/userId 查询匹配则自动通过）→ 渠道退款 → 回调冲正累计 |
| `PayChannelService.java` | **渠道策略注册 + 配置缓存**：`@PostConstruct` 收集所有 `PayChannelStrategy` 实现建 Map → `getConfig()` 用 Caffeine 缓存（TTL 10min）→ `getStrategy()` 按 channelCode 分发 |
| `PayChannelConfigService.java` | 渠道配置 CRUD，insert/update 时调用 `PayChannelService.evictConfig()` 淘汰缓存 |
| `NotifyService.java` | **MQ 通知**：支付成功/关闭 → `MqProducer.send()` → mall-order 消费 → 失败标 bizNotifyStatus=2 → 定时扫描重推（退避 1min/5min/15min/1h，最多 5 次） |
| `ReconService.java` | **对账引擎**：下载→解析→灌入 recon_temp→总额校验 O(1)→逐笔 HashMap 撮合→差异写 recon_result |
| `PayService.java` | **模拟支付**（旧链路过渡）：通过 Feign 查订单 → 直接标支付成功，仅 MOCK 渠道使用 |

#### CRUD 服务（继承 BaseService，标准增删改查）

| 文件 | 对应实体 |
|------|------|
| `PayOrderService.java` | PayOrderEntity |
| `PayRefundService.java` | PayRefundEntity |
| `PayNotifyLogService.java` | PayNotifyLogEntity |
| `PayBizConfigService.java` | PayBizConfigEntity |
| `ReconBatchService.java` | ReconBatchEntity |
| `ReconTempService.java` | ReconTempEntity |
| `ReconResultService.java` | ReconResultEntity |

### 7. support/ — 基础设施

| 文件 | 职责 |
|------|------|
| `AlipayClientFactory.java` | 支付宝 `DefaultAlipayClient` 工厂：Caffeine 缓存 key=channelCode, maxSize=16, TTL=30min。`getClient(config)` 从 configJson 读 gatewayUrl（缺省沙箱），`evict(channelCode)` / `evictAll()` |
| `WechatConfigFactory.java` | 微信 `RSAAutoCertificateConfig` 工厂：Caffeine 缓存 key=channelCode, maxSize=16, TTL=30min。从 configJson 读 apiV3Key + certSerialNo，构造 `RSAAutoCertificateConfig`（含证书自动轮询） |
| `BillCsvParser.java` | 对账单 CSV 解析：支持 GBK/UTF-8 双编码，去反引号前缀，跳过汇总行，返回 `List<Map<String,String>>` |
| `MoneyUtil.java` | 金额换算：`yuanToFen(String yuan)` 元→分，`fenToYuan(Long fen)` 分→元。使用 `BigDecimal` 精度安全 |
| `IdGenerator.java` | 雪花 ID 生成工具（`payOrderNo` / `merchantOrderNo` 需要显式生成） |

## 四、关键设计决策

| 决策 | 说明 |
|------|------|
| 渠道策略模式 | 一个接口 4 个实现，新增渠道不改核心代码 |
| 金额统一用分 | `pay_order.pay_amount` / `total_amount` / `refund_amount` 都是分（bigint），元→分换算只在渠道策略内部 |
| 渠道配置存在数据库 | `pay_channel_config` 表存 appId/公私钥/notifyUrl，admin 端管理；技术参数（超时/重试）在 Nacos YAML |
| Caffeine 双层缓存 | `PayChannelService.getConfig()` TTL 10min（DB 保护层），`AlipayClientFactory` / `WechatConfigFactory` TTL 30min（SDK 对象层），admin 更新时主动淘汰 |
| 支付状态机不缓存 | `pay_order.pay_status` 每次直查 DB，CAS 乐观锁并发控制——涉及资金不允许读到过期数据 |
| HashMap 撮合不 JOIN | 对账日千级数据量，JOIN 在分库分表后不可行，应用层撮合更可控 |
