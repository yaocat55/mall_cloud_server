# 订单-支付解耦方案

> 日期：2026-08-05
> 目的：将 Order 和 Pay 解耦为独立服务，BFF 负责编排，MQ 负责异步状态同步

---

## 一、现状问题

```
【现状】Order 直接依赖 Pay

    BFF → MobileOrderController.submit()
            └─ OrderService.submit()
                 ├─ 建订单
                 ├─ PayFeignClient.create()  ← Order 知道 Pay
                 │    └─ 返回 prepayParams
                 └─ return {orderId, prepayParams, payOrderNo, channelCode}
```

| 问题 | 说明 |
|------|------|
| Order 持有 prepayParams | 订单响应里塞了支付专属字段，前端不知道 prepayParams 来自哪个服务 |
| 无可用渠道接口 | `PayController.channels()` 存在但 BFF 没调、Feign 没暴露、前端拿不到 |
| PayController 闲置 | 6 个 C 端接口全无人调用，channels/create/query/close/refund 形同虚设 |
| ForwardController 透传 | BFF 用 ForwardController 把 order/product/marketing 直接透传到后端，绕过了 BFF 聚合 |
| Order 超时不关 Pay | `sendTimeoutCancelMessage` 取消订单但没调 `PayFeignClient.close()`，支付单残留 |
| Pay 超时不通知 Order | PayOrderCloseJob 的 CLOSED MQ 已加，但 Order 超时才是主逻辑，方向反了 |

---

## 二、目标架构

```
【目标】BFF 编排，Order 和 Pay 互不感知

    前端
      │
      ├─① GET /mobile/v1/pay/channels    → Pay 返回可用渠道列表
      │
      ├─② 用户选渠道
      │
      ├─③ POST /mobile/v1/order/submit   → Order 返回 orderId + payAmount
      │
      ├─④ POST /mobile/v1/pay/create     → Pay 返回 payOrderNo + prepayParams
      │
      └─⑤ 前端拿 prepayParams 拉起 SDK
```

```
    ┌──────────┐         ┌──────────┐
    │  Order   │         │   Pay    │
    │ 服务     │         │  服务    │
    └────┬─────┘         └────┬─────┘
         │                    │
         │   MQ(支付成功)      │
         │◄───────────────────┤  PaySuccessConsumer → 改订单状态
         │                    │
         │   MQ(关单通知)      │
         │◄───────────────────┤  Pay CLOSED → 释放库存（兜底）
         │                    │
         │   Feign close()    │
         │───────────────────►│  Order 超时 → 主动关 Pay
```

---

## 三、超时机制

Order 超时是**主逻辑**，Pay 超时是**安全兜底**。

| 超时 | 谁触发 | 过期时间 | 做什么 |
|------|:---:|:---:|------|
| Order 超时（主） | `sendTimeoutCancelMessage` 延时 MQ | ≤30min | 取消订单 → 调 `PayFeignClient.close()` → 释放库存 |
| Pay 超时（兜底） | `PayOrderCloseJob` 每 10 分钟 | 30min | 关支付单 → 渠道 close → MQ CLOSED → Order 释放库存 |

正常情况下 Pay 超时不会走到——Order 先过期就把 Pay 关了。Pay 超时只在 Order 侧挂了的情况下兜底。

## 四、实施步骤

### Step 1: PayFeignClient + PayInternalController 对齐

**目标**: Feign 和 Internal 只保留真正需要的接口。

| 方法 | 保留 | 理由 |
|------|:---:|------|
| `create` | ✅ | BFF 编排下单后拿 prepayParams |
| `channels` | ✅ 新增 | BFF 暴露给前端选渠道 |
| `query` | ✅ | 前端轮询支付结果 |
| `close` | ✅ | Order 超时取消时主动关 Pay |
| `refund` | ❌ 删除 | 退款走 Order 售后流程，不从前端直调 |
| `queryRefund` | ❌ 删除 | 同上 |

**涉及文件**:
- `mall-pay-client/.../PayFeignClient.java` — 删 `refund`/`queryRefund`，加 `channels`
- `mall-pay/.../controller/internal/PayInternalController.java` — 同上

### Step 2: PayController 清理

**目标**: C 端支付接口只保留前端真正需要的。

| 方法 | 保留 | 理由 |
|------|:---:|------|
| `GET /channels` | ✅ | 前端选择支付方式 |
| `POST /create` | ✅ | 前端拿 prepayParams |
| `POST /query` | ✅ | 前端轮询支付结果 |
| `POST /close` | ❌ | 关单由 Order 超时触发（调 Internal） |
| `POST /refund/apply` | ❌ | 退款走 Order 售后 |
| `POST /refund/query` | ❌ | 同上 |

**涉及文件**:
- `mall-pay/.../controller/mobile/PayController.java` — 保留 3 个方法，删 3 个

### Step 3: OrderService 移除 Pay 依赖

**目标**: Order 不再直接持有 `PayFeignClient`。

| 改动 | 说明 |
|------|------|
| `OrderService` 删除 `PayFeignClient` 字段 | 不再注入 |
| `OrderService.submit()` 删除 pay 创建逻辑 | 不再调 `payFeignClient.create()` |
| `OrderSubmitRespDTO` 删 `payOrderNo`/`channelCode`/`prepayParams` | 这些由 Pay 的接口返回 |

**涉及文件**:
- `mall-order/.../service/OrderService.java`
- `mall-order-client/.../dto/OrderSubmitRespDTO.java`

### Step 4: Order 超时增加关闭 Pay

**目标**: Order 超时取消时主动调 `PayFeignClient.close()`。

| 改动 | 说明 |
|------|------|
| `OrderTimeoutCancelConsumer` 增加调 `PayFeignClient.close()` | Order 超时→关 Pay→关订单→释放库存 |

**涉及文件**:
- `mall-order/.../consumer/OrderTimeoutCancelConsumer.java`（或对应的取消逻辑）

### Step 5: BFF 新建支付聚合

**目标**: mall-mobile-bff 暴露 `/mobile/v1/pay/*` 给前端。

| 新建 | 说明 |
|------|------|
| `MobilePayController` | `GET /channels` + `POST /create` + `POST /query`，调 `PayFeignClient` |

**涉及文件**:
- 新建 `mall-mobile-bff/.../controller/mobile/MobilePayController.java`

### Step 6: BFF order submit 移除 pay 相关

**目标**: BFF 的 `MobileOrderController.submit()` 只返回 orderId + payAmount。

不再聚合 prepayParams——前端单独调 `/mobile/v1/pay/create` 获取。

### Step 7: 网关白名单

在 Gateway `noAuth` 配置中补充：
```
/api/mobile/v1/pay/channels
```

## 五、不做的

| 项目 | 原因 |
|------|------|
| 删 `ForwardController` | 涉及面太广（order/product/marketing 全部透传），单独一个专项 |
| `PayInternalController` 加鉴权 | 短期依赖网关 `/v1/internal/**` 不对外暴露 |
| 退款走支付 C 端接口 | 退款属于售后流程，归属 Order 域 |

## 六、接口清单（最终态）

### 支付服务对外

| 路径 | 调用方 | 说明 |
|------|------|------|
| `POST /v1/internal/pay/create` | Order(BFF编排) | 创建支付单 |
| `POST /v1/internal/pay/query` | BFF | 查询支付状态 |
| `POST /v1/internal/pay/close` | Order(超时) | 关闭支付单 |
| `GET /v1/mobile/pay/channels` | 前端(经BFF) | 可用渠道列表 |
| `POST /v1/mobile/pay/create` | 前端(经BFF) | 创建支付单+拿prepayParams |
| `POST /v1/mobile/pay/query` | 前端(经BFF) | 轮询支付结果 |
| `POST /v1/notify/alipay` | 支付宝 | 回调 |
| `POST /v1/notify/wechat` | 微信 | 回调 |
| Admin CRUD 8 个 | 管理后台 | 配置/查询 |

### 订单服务对外

| 路径 | 调用方 | 说明 |
|------|------|------|
| `POST /v1/mobile/trade/submit` | 前端(经BFF) | 提交订单，返回 orderId + payAmount |
| `POST /v1/mobile/trade/*` | 前端(经BFF) | 订单 CRUD |
| `POST /v1/internal/trade/getDetailByCode` | Pay(回调) | 反查订单详情 |

## 七、MQ 通知（已有，验证即可）

| Topic | 方向 | 用途 |
|------|:---:|------|
| `PAY_NOTIFY` (pay_biz_config 配置) | Pay → Order | 支付成功通知 |
| PAY_CLOSED | Pay → Order | 支付超时关闭通知（兜底） |

---

## 八、step 执行顺序

```
Step 1 (PayFeign + Internal 对齐)
  → Step 2 (PayController 清理)
    → Step 3 (OrderService 移除 Pay 依赖)
      → Step 4 (Order 超时加关 Pay)
        → Step 5 (BFF 新建 MobilePayController)
          → Step 6 (BFF order submit 精简)
            → Step 7 (网关白名单)
```

Step 1-2 可以并行做（都在 Pay 侧），Step 3-4 是 Order 侧，Step 5-7 是 BFF + 网关。
