## 一、与支付宝的核心差异

| | 支付宝 App | 微信 App | 微信小程序 |
|------|:---|:---|:---|
| 下单接口 | `alipay.trade.app.pay` | `POST /v3/pay/transactions/app` | `POST /v3/pay/transactions/jsapi` |
| SDK 返回 | `orderStr`（完整签名字符串） | `prepayId`（只是个标识） | `prepayId`（只是个标识） |
| 服务端二次签名 | **不需要** | **需要** RSA-SHA256 签名 | **需要** RSA-SHA256 签名 |
| 签名串格式 | — | `appId\npartnerId\nprepayId\nnonceStr\ntimeStamp`（5 行） | `appId\ntimeStamp\nnonceStr\nprepay_id=xx`（4 行） |
| 前端签名字段 | — | `sign` | `paySign`（字段名不同！） |
| 前端包字段 | — | `packageValue`: `"Sign=WXPay"` | `package`: `"prepay_id=wx..."` |
| 金额单位 | 元（字符串） | 分（整数） | 分（整数） |
| 回调验签 | RSA2 公钥验签 | APIv3 平台证书验签 + AES-256-GCM 解密 | 同左 |
| 必需参数 | — | appid, mchid, amount, description, out_trade_no, notify_url | 同 App + `payer.openid` |

核心结论：**微信 `prepay_id` 的二次签名 SDK 不帮你做**，必须服务端自己用 `java.security.Signature` SHA256withRSA 签名。App 和小程序的签名串格式不同、返回字段名不同，不能共用一套代码。

## 二、SDK 选型：`wechatpay-java` v0.2.17

### 为什么不用手写 HTTP

`wechatpay-java` 官方 SDK 内置完整的 HTTP 客户端链（基于 OkHttp），不是手写。核心对象是 `RSAAutoCertificateConfig`，它内部封装：

- APIv3 请求签名（`Authorization` 头 / SHA256-RSA2048）
- 平台证书自动下载 + 后台线程轮换（`AutoCertificateService`，每 60 分钟检查）
- OkHttp 连接池（可注入自定义 `OkHttpClient`） + 双域名容灾（可开启 `enableRetryMultiDomain()`）

与 `alipay-sdk-java` 对比：

| | alipay-sdk-java | wechatpay-java |
|------|:---|:---|
| 核心对象 | `DefaultAlipayClient`（HTTP 客户端） | `RSAAutoCertificateConfig`（配置 + 签名 + 证书管理） |
| HTTP 层 | 内置旧版 HttpClient | 内置 OkHttp（`DefaultHttpClientBuilder`） |
| 证书管理 | 无（公钥手动配置） | `AutoCertificateService` 自动下载 + 后台轮换 |
| Service 对象 | 无（直接 `client.execute(request)`） | `AppService` / `JsapiService` / `RefundService` 封装请求/响应 |
| Maven artifact | `com.alipay.sdk:alipay-sdk-java` | `com.github.wechatpay-apiv3:wechatpay-java` |

### Maven 依赖

```xml
<dependency>
    <groupId>com.github.wechatpay-apiv3</groupId>
    <artifactId>wechatpay-java</artifactId>
    <version>0.2.17</version>
</dependency>
```

## 三、工厂模式：WechatConfigFactory

### 缓存的不是 HTTP 客户端，是 `RSAAutoCertificateConfig`

```java
// SDK 的 Config 对象一次性构建，长期复用
RSAAutoCertificateConfig config = new RSAAutoCertificateConfig.Builder()
    .merchantId(channelConfig.getMerchantId())
    .privateKey(channelConfig.getPrivateKey())       // 商户私钥 PEM 字符串
    .merchantSerialNumber(serialNo)                   // 从 configJson 中读取
    .apiV3Key(apiV3Key)                               // 从 configJson 中读取
    .build();
```

`configJson` 字段内容（JSON 字符串）：
```json
{
  "apiV3Key": "32字节APIv3密钥",
  "certSerialNo": "5157F09E****",
  "gatewayUrl": "https://api.mch.weixin.qq.com"
}
```

Caffeine 缓存 key=channelCode，maxSize=16，TTL=30min。

`AppService` / `JsapiService` / `RefundService` 是轻量对象，每次请求 build 即可：
```java
AppService appService = new AppService.Builder().config(cachedConfig).build();
JsapiService jsapiService = new JsapiService.Builder().config(cachedConfig).build();
RefundService refundService = new RefundService.Builder().config(cachedConfig).build();
```

### 与支付宝工厂对比

| | AlipayClientFactory | WechatConfigFactory |
|------|------|------|
| 缓存对象 | `DefaultAlipayClient` | `RSAAutoCertificateConfig` |
| 缓存 key | channelCode | channelCode |
| 配置来源 | `configJson.gatewayUrl` | `configJson.apiV3Key` + `configJson.certSerialNo` |
| 过期策略 | TTL 30min | TTL 30min |
| 业务 Service | 无（直接调 client.execute） | `AppService` / `JsapiService` / `RefundService` 每次 build |

## 四、二次签名实现（关键）

### 支付宝：一行代码

```java
response.getBody();  // orderStr，前端原样透传
```

### 微信 App：7 步

```java
// 1. 调 SDK 下单
PrepayResponse resp = appService.prepay(request);
String prepayId = resp.getPrepayId();

// 2. 生成随机串
String nonceStr = UUID.randomUUID().toString().replace("-", "").substring(0, 32);

// 3. 秒级时间戳
String timeStamp = String.valueOf(System.currentTimeMillis() / 1000);

// 4. 拼签名串（App 支付 5 行）
String signStr = appId + "\n"
    + partnerId + "\n"
    + prepayId + "\n"
    + nonceStr + "\n"
    + timeStamp;

// 5. SHA256withRSA 签名
java.security.Signature sig = java.security.Signature.getInstance("SHA256withRSA");
sig.initSign(getPrivateKey());
sig.update(signStr.getBytes(StandardCharsets.UTF_8));
String sign = Base64.getEncoder().encodeToString(sig.sign());

// 6. 组装返回
// 返回给前端的 prepayParams JSON：
{
  "appId": "wx...",
  "partnerId": "190000...",
  "prepayId": "wx...",
  "nonceStr": "...",
  "timeStamp": "...",
  "packageValue": "Sign=WXPay",
  "sign": "base64签名"
}
```

### 微信小程序：签名串不同

```java
// 小程序签名串（4 行，不含 partnerId）
String signStr = appId + "\n"
    + timeStamp + "\n"
    + nonceStr + "\n"
    + "prepay_id=" + prepayId;

// 签名后返回给前端的 prepayParams JSON：
{
  "appId": "小程序 AppID",
  "timeStamp": "...",
  "nonceStr": "...",
  "package": "prepay_id=wx...",
  "signType": "RSA",
  "paySign": "base64签名"    // ← 字段名是 paySign 不是 sign
}
```

### 对照表

| | 签名串 | 行数 | 签名字段名 | 包字段 |
|------|------|:---:|------|------|
| App 支付 | `appId\npartnerId\nprepayId\nnonceStr\ntimeStamp` | 5 | `sign` | `packageValue="Sign=WXPay"` |
| 小程序支付 | `appId\ntimeStamp\nnonceStr\nprepay_id=prepayId` | 4 | `paySign` | `package="prepay_id=wx..."` |

## 五、回调通知处理

### 与支付宝回调的差异

支付宝：`request.getParameterMap()` 提取参数 → `AlipaySignature.rsaCheckV1()` 验签。

微信：需要 HTTP 请求头（`Wechatpay-Signature` 等）+ raw body → `NotificationParser.parse()` 一步完成验签 + 解密。

```java
// Controller 提取头
String wechatpaySignature = request.getHeader("Wechatpay-Signature");
String wechatpayTimestamp = request.getHeader("Wechatpay-Timestamp");
String wechatpayNonce = request.getHeader("Wechatpay-Nonce");
String wechatpaySerial = request.getHeader("Wechatpay-Serial");

// 策略内部用 SDK 验签 + 解密
NotificationParser parser = new NotificationParser(config);
Transaction transaction = parser.parse(
    wechatpaySignature, wechatpayTimestamp,
    wechatpayNonce, wechatpaySerial, rawBody,
    Transaction.class);
```

解密后得到 `Transaction` 对象，映射到 `PayNotifyMessage`：

| Transaction 字段 | PayNotifyMessage 字段 |
|------|------|
| `outTradeNo` | `merchantOrderNo` |
| `transactionId` | `channelTradeNo` |
| `tradeState == SUCCESS` | `payStatus = 20` |
| `amount.total` | `payAmount`（已是分，无需转换） |
| `successTime`（rfc3339） | `successTime`（Date） |

## 六、实现步骤

### Step 1: 添加 SDK 依赖

**文件**: `mall-pay/pom.xml`

### Step 2: 创建 WechatConfigFactory

**新建文件**: `mall-pay/src/main/java/cn/net/mall/pay/support/WechatConfigFactory.java`

- Caffeine 缓存 `RSAAutoCertificateConfig`（key=channelCode）
- 从 `configJson` 解析 `apiV3Key`、`certSerialNo`
- 提供 `getConfig(channelConfig)`、`evict(channelCode)`

### Step 3: 创建 WechatPayStrategy

**新建文件**: `mall-pay/src/main/java/cn/net/mall/pay/channel/wechat/WechatPayStrategy.java`

- `channelCode()` = `"WECHAT_PAY"`
- `prepay()`: `AppService.prepay()` → 获取 `prepayId` → 二次签名（App 格式 5 行）
- `query()`: `JsapiService.queryOrderByOutTradeNo()`
- `close()`: `JsapiService.closeOrder()`
- `refund()`: `RefundService.create()`
- `queryRefund()`: `RefundService.queryByOutRefundNo()`
- `verifyNotify()`: `NotificationParser` 验签
- `parseNotify()`: `NotificationParser.parse()` → 映射 `PayNotifyMessage`

### Step 4: 创建 WechatMiniStrategy

**新建文件**: `mall-pay/src/main/java/cn/net/mall/pay/channel/wechat/WechatMiniStrategy.java`

- `channelCode()` = `"WECHAT_MINI"`
- `prepay()`: `JsapiService.prepay()`（需要 `payer.openid`）→ 二次签名（小程序格式 4 行，返回 `paySign`）
- 其余方法同 `WechatPayStrategy`（query/close/refund 共用 SDK Service）

### Step 5: 修复 WechatNotifyController

**修改文件**: `mall-pay/src/main/java/cn/net/mall/pay/controller/notify/WechatNotifyController.java`

- Controller 提取 HTTP 头传入策略
- 策略内部用 `NotificationParser` 处理验签 + 解密
- 当前传 `null` 的地方替换为实际值

### Step 6: 数据库种子数据

**修改文件**: `mall-pay/sql/mall_pay.sql`

添加 `WECHAT_PAY` 和 `WECHAT_MINI` 两条配置（商户号、密钥留占位，真实值通过 admin 配置录入）
