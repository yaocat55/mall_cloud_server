**已配置就绪（数据库 cloud_mall_pay）：**
- `pay_channel_config`: ALIPAY（appId=9021000166643082, 沙箱密钥, status=1 启用）+ WECHAT_PAY / WECHAT_MINI（占位，真实商户号待配）
- `pay_biz_config`: MALL_ORDER（topic=PAY_NOTIFY_MALL_ORDER, tag=PAY_SUCCESS）

**已确认的设计决策：**
- **方案 A（业界主流）**：前端 → mall-order → mall-pay 单一请求链，前端 1 个请求拿到订单 + 凭证；支付核心全在 pay，order 只做服务编排透传
- **渠道选择**：前端收银台调 `/channels` 拿可用渠道 → 用户点选 → channelCode 随下单请求透传 → pay 校验 + 分发策略
- **先落库后 prepay**：pay_order 落库失败即终止，永不调渠道；落库字段零依赖 prepay 返回值
- **渠道配置使用 Caffeine 本地缓存**：pay_channel_config 读多写极少，Caffeine 缓存（TTL 10min），Admin 修改即时淘汰；支付宝/微信 SDK 客户端实例同理由对应工厂类缓存（TTL 30min）；**支付状态机不缓存**，每次直读 DB 保证实时性
- **对账引擎分库分表预留**：PlatformDataQuery 接口抽象平台侧数据查询，当前单库实现 DefaultPlatformDataQuery，未来分片遍历/只读副本/CDC 汇聚三种方案可无缝替换
- **退款三方交叉验证**：总额校验阶段同时对 CSV 退款项 SUM → pay_refund 成功退款 SUM → pay_order.refund_amount，三个数字不一致立即可见
