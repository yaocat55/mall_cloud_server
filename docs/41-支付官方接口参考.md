## 二、核对结论：拉起支付的精确时序（以官方为准）

### 2.1 支付宝 App 支付（官方文档确认）

```
移动端请求服务端（携带订单信息）
  → 服务端调用 alipay.trade.app.pay（服务端用私钥签名）
  → 服务端返回 orderStr（签名后的字符串）
  → 移动端把 orderStr 原样交给 SDK：PayTask.payV2(orderStr)（Android）/ AlipaySDK payOrder:fromScheme:（iOS）
  → SDK 拉起支付宝 App
  → 用户在支付宝内完成支付
  → 支付宝异步通知服务端（notify_url）→ 服务端验签并更新订单状态
```

**`orderStr` 关键字段**（官方原文摘录）：

| 字段 | 说明 |
|------|------|
| `out_trade_no` | 商户订单号（唯一）= 我方 `merchant_order_no` |
| `total_amount` | 订单总金额（**元**，字符串） |
| `subject` | 订单标题 |
| `product_code` | 固定 `QUICK_MSECURITY_PAY` |
| `notify_url` | 异步通知回调地址 |
| `sign` / `sign_type` | 签名 / 签名算法（RSA2） |
| `app_id` / `charset` / `timestamp` / `method` / `version` | 应用标识、字符集、时间戳、接口名、版本 |

> 前端**原样透传 orderStr，不做任何签名**——orderStr 已含服务端私钥签好的 `sign`。

### 2.2 微信 App 支付

```
服务端调用 POST /v3/pay/transactions/app（APIv3 签名）
  → 返回 {"prepay_id":"wx..."}
  → 服务端二次签名（RSA-SHA256，商户私钥）
  → 返回签好的调起参数给前端
  → 前端调微信 SDK 拉起支付
  → 用户在微信内支付
  → 微信异步通知服务端（notify_url）→ 平台证书验签 + AES-256-GCM 解密 → 更新状态
```

> 微信和支付宝最大的差异：支付宝 `orderStr` 是完整签名字符串，前端**原样透传**；
> 微信 `prepay_id` 只是个标识，**服务端必须二次签名**才能得到前端可用的调起参数。
> **签名不能放客户端做**——商户私钥在服务端，客户端持有的 appId 签名没有意义。
> 金额单位：微信 APIv3 用**分**（`amount.total`），支付宝用**元**（`total_amount`）。

### 2.3 微信小程序支付（JSAPI）

```
服务端调用 POST /v3/pay/transactions/jsapi（需传入 payer.openid）
  → 返回 {"prepay_id":"wx..."}
  → 服务端二次签名（RSA-SHA256，小程序密钥）
  → 返回签好的调起参数给前端
  → 前端调 wx.requestPayment() 拉起支付
  → 用户在微信内支付
  → 微信异步通知服务端 → 验签 + AES-256-GCM 解密 → 更新状态
```

### 2.4 ⚠️ 微信二次签名：App 与小程序的关键区别

> 这是踩坑最多的环节——两种终端的**签名字符串和返回字段名都不同**。

**App 支付二次签名：**

签名字符串（`\n` 分隔，5 行）：
```
appId
partnerId
prepayId
nonceStr
timeStamp
```

签名后返回给前端的字段（注意字段名）：
```json
{
  "appId": "wx...",
  "partnerId": "190000...",
  "prepayId": "wx...",
  "nonceStr": "随机32位字符串",
  "timeStamp": "秒级时间戳（字符串）",
  "packageValue": "Sign=WXPay",
  "sign": "用商户私钥 RSA-SHA256 签名后 Base64"
}
```

前端调用：Android `IWXAPI.sendReq()` / iOS `WXApi sendReq:`，传入 `PayReq` 对象。

**小程序支付二次签名：**

签名字符串（`\n` 分隔，4 行，**不含 partnerId**）：
```
appId
timeStamp
nonceStr
prepay_id=wx...
```

签名后返回给前端的字段（注意：字段名是 `paySign` 不是 `sign`，是 `package` 不是 `packageValue`）：
```json
{
  "appId": "小程序 AppID",
  "timeStamp": "秒级时间戳（字符串）",
  "nonceStr": "随机32位字符串",
  "package": "prepay_id=wx...",
  "signType": "RSA",
  "paySign": "用商户私钥 RSA-SHA256 签名后 Base64"
}
```

前端调用：`wx.requestPayment({ timeStamp, nonceStr, package, signType, paySign })`

**App vs 小程序对照表：**

| | App 支付 | 小程序支付 |
|------|------|------|
| 下单接口 | `POST /v3/pay/transactions/app` | `POST /v3/pay/transactions/jsapi` |
| 必填参数 | appid, mchid, amount, description, out_trade_no, notify_url | 同 App + `payer.openid` |
| 签名串 | `appId\npartnerId\nprepayId\nnonceStr\ntimeStamp` | `appId\ntimeStamp\nnonceStr\nprepay_id=wx...` |
| 签名算法 | RSA-SHA256（SHA256withRSA） | 同 |
| 返回签名字段 | `sign` | `paySign` |
| 返回包字段 | `packageValue`: `"Sign=WXPay"` | `package`: `"prepay_id=wx..."` |
| 签名密钥 | 商户私钥（apiclient_key.pem） | 同（共用商户号）或小程序独立密钥 |
| 前端拉起 | Android `PayReq` / iOS `WXApi sendReq:` | `wx.requestPayment()` |

> **关键教训**：微信 SDK 只负责 APIv3 请求的签名（`Authorization` 头），
> **prepay_id 的二次签名要服务端自己实现**——拼签名串 + `java.security.Signature` SHA256withRSA + Base64。
> 两个渠道的签名串格式不同、返回字段名不同，不能用一套代码覆盖。

### 2.3 微信回调通知（官方文档确认，供回调实现用）

- 回调请求体：`id`（唯一编号）、`create_time`（rfc3339）、`event_type`（`TRANSACTION.SUCCESS`）、`resource`（密文）
- 验签头：`Wechatpay-Serial` / `Wechatpay-Signature` / `Wechatpay-Timestamp` / `Wechatpay-Nonce`
- 验签串 = `Wechatpay-Timestamp` + `\n` + `Wechatpay-Nonce` + `\n` + 请求体 + `\n`
- 解密：APIv3 密钥 + `nonce` + `associated_data`，AES-256-GCM 解 `resource.ciphertext`
- 成功应答：**5 秒内**返回 HTTP `200`/`204`；失败返回 `4XX`/`5XX` + 应答报文（`code:"FAIL"`）
- 重试：`15s/15s/30s/3m/10m/20m/30m/30m/30m/60m/3h/3h/3h/6h/6h`，最多 **15 次**
- 解密后字段：`appid`、`mchid`、`out_trade_no`、`transaction_id`、`trade_state`（SUCCESS/REFUND/NOTPAY/CLOSED/REVOKED/USERPAYING/PAYERROR）、`amount.total/payer_total`、`success_time`、`payer.openid` 等

## 三、拉起时序落地方案（对应本项目代码）

| 前端场景 | 调用 | 返回 | 前端动作 |
|---------|------|------|---------|
| 收银台渲染 | `GET /v1/mobile/pay/channels` | 可用渠道列表（编码+名称，无密钥） | 渲染支付方式 |
| 用户选渠道后发起支付 | `POST /v1/mobile/pay/create`（经 mall-order 透传 channelCode） | `PayCreateResult.prepayParams` | 支付宝透传 orderStr / 微信拼签名调起 |

对应代码：
- `PayCoreService.create(PayCreateDTO)` → 建支付单 + 调 `PayChannelStrategy.prepay()` → 返回 `PayCreateResult{prepayParams}`
- `AlipayChannelStrategy.prepay()` → 返回 `orderStr`；`WechatChannelStrategy.prepay()` → 返回 `prepay_id`
- `PayController.channels()` → `PayChannelService.listAvailableChannels()`
